# Patron API Flow

Send requests to browse the menu, check ingredient quantities, view dish details, and place an order.

## 1. Start Browsing

### Request

The client sends an HTTP request to `https://{{baseUrl}}/dishes` to get a list of available dishes. To view dishes in a particular category, include `filter=category.eq~{CategoryName}` in the query parameters.

```
curl -X GET "https://{{baseUrl}}/dishes?filter=category.eq~Appetizer"
```

### Response

If the request was successful, the server responds with a `200 OK` status code with the response body containing a `results` array of the dishes in the identified category. Each object includes the dish's `id`, `name`, `description`, `category`, `price` (in cents), `preparation_time`, and `ingredients`.

## 2. Check Ingredient Quantities

### Request

The client sends an HTTP request to `https://{{baseUrl}}/ingredients/{id}` to get the details of a dish's ingredients. To view the in-stock quantity of the ingredient, include the `name` and `in_stock_qty` fields in the query parameters.

```
curl -X GET "https://{{baseUrl}}/ingredients/id?fields=name|in_stock_qty"
```

### Response

If the request was successful, the server responds with a `200 OK` status code with the response body containing the dish's ingredient name and in-stock quantity.

```json
{
    "id": "6af1f160b7c431c173cf9d41",
    "name": "Eggplant",
    "in_stock_qty": 43
}
```

## 3. View Dish Details

### Request

The client sends an HTTP request to `https://{{baseUrl}}/dishes/{id}` to get the details of a dish. 

```
curl -X GET "https://{{baseUrl}}/dishes/{id}"
```

### Response

If the request was successful, the server responds with a `200 OK` status code with the response body containing the dish's details, such as its `name`, `description`, `price`, and `ingredients`.

## 4. Place an Order

### Request

The client sends a POST HTTP request to `https://{{baseUrl}}/orders` to place an order. The request body must include values in the `name` and `dish_ids` fields.

```
curl -X POST "https://{{baseUrl}}/orders" \
-H 'accept: application/json' \
-H 'Content-Type: application/json' \
-d {
  "name": "Richard",
  "table_number": 25,
  "dish_ids": [
    "6af1f160b7c431c173cf9d55",
  ],
  "scheduled at": null,
}
```

### Response

If the request was successful, the server responds with a `201 Created` status code with the response body containing the order's details, including its `id`, `status`, and `priority`.

```json
{
    "id": "6b03612d2adf95b5cb2ffd1e",
    "created_at": "2026-11-22T21:39:57.062Z",
    "updated_at": "2026-11-22T21:39:57.062Z",
    "scheduled_at": null,
    "table_number": 25,
    "status": "Received",
    "priority": 3,
    "dish_ids": [
        "6af1f160b7c431c173cf9d55"
    ],
}
```

## 5. Order Confirmation

Once the order is placed, the patron receives a receipt of confirmation, and the order details are sent to the restaurant staff to prepare the order. See [Staff Flow](./staff).
